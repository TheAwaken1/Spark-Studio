Recovery
Quelque chose est bloqué ou cassé ? Chaque action ci-dessous dit exactement ce qu'elle fait — aucune ne supprime les modèles téléchargés.

      

        

          
 Vider les runs terminés

          
Retire les runs terminés de la liste. L'historique des runs reste en base ; rien en cours n'est touché.

          
        

        

          
 Supprimer les containers orphelins

          
Retire les containers restants spark-vllm-* / sparkrun_* qu'aucun run live ne contrôle. Les containers appartenant à des workloads en cours, les jobs sparkrun actifs, et tout ce que vous gérez vous-même (comme vllm_node) ne sont jamais touchés.

          
        

        

          
 Réinitialiser le cache du registry

          
Supprime le miroir local des repos de recipes communautaires et le cache YAML forgé, puis retélécharge des copies fraîches en arrière-plan. Corrige les listings de recipes obsolètes ou corrompus.

          
        

        

          
 Réinitialiser la base de l'app

          
Supprime les recipes sauvegardées, l'historique des runs, l'historique des benchmarks et evals. N'arrête pas un modèle en cours et ne supprime pas les fichiers de modèle téléchargés. Il n'y a pas d'annulation.

          
        

        

          
 Copier le rapport de bug

          
Copie un rapport markdown — santé système, run actif, recipe (secrets masqués), et les 300 dernières lignes de log — prêt à coller dans une issue GitHub ou à donner à un agent.

          
        

        

          
 Reset complet (terminal)

          
Si l'app ne veut pas du tout démarrer, lancez ces commandes depuis le dossier d'install :

          
rm -f data/spark_studio.db     # settings/historique uniquement
rm -rf env && ./start.sh       # rebuild env Python
./start.sh --doctor            # rapport de santé
